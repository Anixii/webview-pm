# WebView и MBANK Bridge: памятка для PM

Эта памятка содержит технические понятия, которые PM использует при обсуждении WebView с frontend, backend и технической поддержкой. Она предназначена для планирования и подготовки запросов; детали реализации согласуются с командами проекта.

## Как связаны WebView и Bridge

WebView — веб-страница, открытая внутри мобильного приложения МБанк. MBANK WebView Bridge — согласованный способ, которым страница просит мобильное приложение выполнить native-действие: открыть deeplink, начать платёж, показать PDF или закрыть WebView.

Bridge не заменяет API проекта и не отменяет серверную авторизацию. Он отвечает за связь WebView с возможностями мобильного приложения. Для новых WebView используется Bridge; старые схемы запуска действий через перехват URL или AJAX не следует закладывать в новый сценарий.

## Основные термины

### Origin и `allowedOrigins`

**Origin страницы** — адрес сайта, с которого загружена WebView, например `https://bimed.kg`. Это источник страницы, а не адрес целевого экрана, куда ведёт deeplink.

**`allowedOrigins`** — список origins, которым мобильное приложение разрешает использовать Bridge. Его настраивает техническая поддержка. Для dev, test и prod origins запрашиваются отдельно. PM получает правильные адреса у frontend-команды и передаёт отдельный запрос на каждое окружение.

Если Bridge передаёт HTTP/HTTPS URL в качестве callback, result, PDF или внешней ссылки, такой URL тоже должен соответствовать разрешённой конфигурации. При `forbiddenOrigin` нужно сверить origin страницы и переданный URL с настройкой нужного окружения и обратиться к технической поддержке.

### Capability

**Capability** — разрешение на конкретное native-действие. Базовых разрешений «по умолчанию» нет. PM просит frontend перечислить действия, которые нужны пользовательскому flow; frontend называет Bridge events и capabilities. PM передаёт подтверждённый список на настройку.

| Действие в сценарии | Bridge event | Capability |
| --- | --- | --- |
| Закрыть WebView | `app.close` | `close` |
| Запросить native-авторизацию и вернуться в WebView | `auth.required` | `authResume` |
| Запустить мобильный платёж | `payment.start` | `payments` |
| Открыть системное меню отправки текста | `share.text` | `share` |
| Показать PDF | `pdf.previewUrl`, `pdf.previewBase64` | `pdfPreview` |
| Открыть внешнюю HTTP/HTTPS-ссылку | `external.open` | `externalLinks` |
| Открыть deeplink внутри мобильного приложения | `deepLink.open` | `deepLinks` |
| Отправить Firebase Analytics event/property | `firebaseAnalytics.logEvent`, `firebaseAnalytics.setUserProperty` | `analytics` |
| Отправить Adjust event | `adjust.logEvent` | `adjust` |
| Использовать biometric storage | `biometry.isAvailable`, `biometry.save`, `biometry.read` | `biometry` |
| Получить device report | `device.report` | `deviceReport` |

Таблица помогает PM проверить запрос frontend, но PM не должен самостоятельно выбирать capabilities вместо команды разработки. Если при вызове возникает `missingCapability`, это означает, что нужное разрешение не включено в конфигурацию; следует сверить список с frontend и запросить настройку.

### Callback/result URL

Это URL, куда сценарий возвращает пользователя или передаёт результат. Он может не использоваться; необходимость зависит от проекта. PM уточняет у команды проекта, нужен ли такой адрес и какое значение использовать. Если он не нужен, в запросе явно написать «не используются». Если URL требуется добавить или настроить позже, PM может обратиться к ДЦРМС через Telegram.

Для платежа frontend сначала получает у backend данные/подтверждение платежа, затем запускает Bridge event `payment.start`. Если flow возвращается на `resultUrl`, этот URL заранее согласуется и входит в разрешённую конфигурацию.

## Deeplink

Deeplink — адрес, который направляет пользователя в конкретный экран или сервис мобильного приложения. Для вызова из WebView используется Bridge event `deepLink.open`, которому нужна capability `deepLinks`. Такой адрес может иметь схему приложения, например `mbank://...`.

Процесс запроса:

1. PM уточняет у команды проекта точную страницу, на которую нужно привести пользователя. Подходит обычная ссылка, например `https://google.com/`; в запросе указывается фактическая ссылка проекта.
2. В Telegram обращается к технической поддержке ДЦРМС, называет сервис и передаёт ссылку на целевую страницу.
3. Если поддержка просит partner name, PM берёт его из письма ДЦРМС, отправленного после создания сервиса.
4. Для test и prod запрашиваются отдельные deeplinks и используются разные partner name, поскольку это разные WebView.
5. Frontend использует выданный deeplink вместе с capability `deepLinks`.

`allowedOrigins` и deeplink решают разные задачи: origin разрешает сайту использовать Bridge, а deeplink определяет место назначения. Если deeplink открывает другой WebView, он открывается поверх текущей; после закрытия нового flow пользователь возвращается в исходный WebView.

## Прочие Bridge-действия, о которых может спросить PM

- **Внешняя ссылка:** `external.open`, capability `externalLinks`; открывается HTTP/HTTPS URL.
- **PDF:** `pdf.previewUrl` или `pdf.previewBase64`, capability `pdfPreview`. Предпочтительный сценарий — доступный по URL PDF.
- **Авторизация:** `auth.required`, capability `authResume`. Это явный запрос к приложению запустить авторизацию и вернуть пользователя в WebView; Bridge event не заменяет обычную авторизацию проекта через backend.
- **Закрытие:** `app.close`, capability `close`; закрывает WebView и может вернуть результат приложению.
- **Платёж:** `payment.start`, capability `payments`; точный способ оплаты и payload согласуются с ДЦРМС и frontend/backend команды.

## Типовые проблемы и следующий шаг PM

| Что видит команда | Возможный смысл | Что может сделать PM |
| --- | --- | --- |
| `missingCapability` | Нужное действие не включено в конфигурацию сервиса. | Сверить event/capability с frontend и запросить включение у технической поддержки. |
| `forbiddenOrigin` | Origin страницы или HTTP/HTTPS URL не разрешён. | Сверить окружение и адреса; отправить недостающий origin отдельным запросом. |
| `bridgeUnavailable` | Bridge недоступен, ещё не готов или отсутствует в версии приложения. | Передать информацию frontend и технической поддержке; выяснить доступность Bridge в тестовой версии приложения. |
| `unsupportedAction` | Мобильное приложение не поддерживает event или handler. | Сверить event с frontend и поддержкой MBANK. |

Технический код ошибки — информация для диагностики. Пользователю показывают понятное сообщение; технические подробности PM передаёт разработчикам или поддержке.

## Что PM готовит для Bridge-настройки

- название сервиса;
- одно окружение на запрос;
- origin страницы этого окружения;
- список capabilities, полученный от frontend;
- callback/result URL или явное указание, что они не используются;
- ссылку на страницу назначения, если отдельно запрашивается deeplink.

Значения домена/origin, capabilities, callback/result URL и deeplink нельзя угадывать. Если какого-то значения нет, PM запрашивает его у соответствующей команды.
