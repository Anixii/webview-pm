# Подготовка проекта из пустой папки

Плагин хранит знания и skills. Исходники React template находятся в отдельном Git-репозитории. По запросу создать проект bootstrap получает выбранную версию шаблона, копирует исходники в пустую рабочую папку, устанавливает зависимости и выполняет проверки. Skills остаются частью установленного плагина.

## Источник

[template-source.json](../template-source.json) содержит:

- `schemaVersion`: версия формата, сейчас `1`;
- `repository`: Git URL шаблона;
- `ref`: полный commit или release tag;
- `packageManager`: `yarn` для текущего MBANK template;
- `verificationScripts`: проверки из `package.json`, сейчас `lint:type` и `build`.

GitHub-репозиторий шаблона пока не создан, поэтому `repository` и `ref` равны `null`. До их настройки bootstrap останавливается до записи файлов в рабочую папку. Пользователь может передать источник аргументами для конкретного запуска. Использование другого источника не означает автоматического изменения конфигурации установленного плагина.

Для релиза предпочтителен полный проверенный commit. Tag допустим: bootstrap разрешает его в точный commit и записывает его в проект. Доступ к приватному репозиторию и registry обеспечивается средствами окружения пользователя; секреты не помещаются в конфигурацию плагина.

## Запуск

Нужны Git, Node.js и выбранный менеджер пакетов. Поддерживаемую версию Node проверяют по опубликованному template, его `engines` и документации релиза. Bootstrap не устанавливает глобальные программы. Для приватного `md-glyphs` или других зависимостей нужно доступное registry-подключение.

```sh
node <plugin-root>/scripts/bootstrap-project.mjs --target <empty-project-folder>
```

`<plugin-root>` — абсолютный путь к установленному плагину, определённый из местоположения skill. Не считать, что в целевом проекте есть папка `plugins/`.

Для task-local источника:

```sh
node <plugin-root>/scripts/bootstrap-project.mjs \
  --target <empty-project-folder> \
  --repository <template-git-url> \
  --ref <full-commit-or-release-tag>
```

`--package-manager yarn|npm|pnpm` явно выбирает менеджер для конкретного источника. Используется его lockfile и строгая установка: Yarn 1 `--frozen-lockfile`, современный Yarn `--immutable`, npm `ci`, pnpm `--frozen-lockfile`. При нескольких lockfiles выбор остаётся явным; bootstrap не пересоздаёт lockfile для другого менеджера.

`--copy-only` выгружает исходники без установки и проверок. Использовать этот режим для чтения кода в отдельной временной папке или по запросу только скачать шаблон. Такой результат не объявляется готовым приложением.

## Результат и ошибки

Получение и подготовка исходников проходят во временной папке. Bootstrap отказывается перезаписывать непустую целевую папку. Копируются tracked source files; Git metadata, установленные зависимости, результаты сборки, секретные env-файлы и настройки среды разработки плагина в новый проект не переносятся. Образцы env-конфигурации остаются доступными.

В `.webview-template.json` записываются источник, точный commit и состояние копирования, установки и проверок. Существующая пустая папка сохраняется, поэтому bootstrap можно запускать непосредственно из открытого workspace. После ошибки копирования сохраняются уже созданные файлы и состояние неудачи; после ошибки установки или сборки сохраняются исходники. Агент исправляет причину и повторяет соответствующий шаг. Для повторного bootstrap нужна отдельная пустая папка. Не удалять проект, чтобы скрыть неудачную установку.

Подготовка считается успешной после установки зависимостей и прохождения настроенных проверок. Bootstrap не запускает dev server. Агент сообщает команду ручного запуска из реального `package.json`, затем продолжает заказанную разработку экрана или формы.
